# 2026-09-29 — дерево: отбор по типу показывает ветки (beads-web-acj)

Раньше отбор «Milestone» в виде дерева показывал только сами вехи: страница
передавала дереву `filterBoardTypes(filteredBeads, typeFilter)` — это
оставляет лишь задачи выбранного типа, а дерево добавляет к ним только
предков. Теперь `matchedIds` для дерева считает `matchTreeTypes` в
`src/lib/tree.ts`: задача проходит, если её тип совпадает с выбранным или
у неё есть предок этого типа. Родителей она берёт той же `linkParents`, что и
само дерево (сначала `parent_id`, затем список `children` у родителя), поэтому
ветки в отборе и на экране совпадают. Ответ для каждой задачи запоминается,
так что каждая проходится один раз; кольцо родителей обрывает обход с ответом
«нет». Остальные фильтры действуют как раньше: на вход идут уже
отфильтрованные задачи, и потомок вехи, не прошедший поиск, в отбор не
попадает (веха над ним остаётся видна сама). При «All types» правило прежнее —
всё, кроме story. Идеи (story) под вехой не показываются, пока не выбран тип
Story. Отбор «Epic» теперь тоже показывает эпики с их задачами. Доска не
изменилась.

**Что проверить первым, если сломается.** Отбор снова показывает одни вехи —
смотреть `treeMatchedIds` в `src/app/project/kanban-board.tsx`: туда должен
идти полный список `beads` вторым аргументом, не `filteredBeads`. Ветка видна
не целиком — сравнить, как `linkParents` связывает эту задачу с родителем.

**Оставлено как есть.** Отбор доски по вехе не делается (решение эпика
beads-web-0l7). Вехи первыми на корне и полоса готовности у вехи сделаны
раньше, в beads-web-0l7.1 и 0l7.2.
