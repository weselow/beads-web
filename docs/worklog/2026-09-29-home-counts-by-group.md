# 2026-09-29 — главная: счётчики и круговая диаграмма по группам статусов (beads-web-5fk.5)

Главная больше не считает задачи сама. Сервер считает их по четырём группам
(`active`, `wip`, `frozen`, `done`) в одном месте — `count_by_group` в
`server/src/routes/statuses.rs` — и отдаёт результат двумя путями: полем
`counts` в ответе `/api/beads` и полем `cachedCounts` в `/api/projects` (из
таблицы `project_bead_counts`, куда те же числа пишет `upsert_counts_cache` в
`server/src/routes/beads.rs`). Правила: статус ищется в списке статусов проекта
(тот же, что отдаёт `/api/statuses`, через общий кэш `StatusCache`); статуса нет
в списке — считается активным; старые `done`/`resolved` считаются как `closed`,
`pending` — как `open`; `tombstone` не считается. Список проекта читается,
только если среди задач есть не встроенный статус, — иначе хватает встроенного
списка bd, и лишнего вызова `bd statuses` нет. Частичное чтение (bd CLI с
`updated_after`) не пишет счётчики и не отдаёт `counts` — раньше оно записывало
в кэш заниженные числа. Миграция 4 добавила колонки `active`, `wip`, `frozen`,
`done`; старые `open`/`in_progress`/`inreview`/`closed` остались и заполняются
как раньше, чтобы откат на 0.13 видел свежие числа. На странице временный
`src/lib/home-counts.ts` удалён, `use-projects.ts` берёт `counts` из ответа, а
если их нет — показывает ошибку на карточке. Диаграмма — четыре доли: Active,
In progress, Frozen, Done.

**Почему так.** У новых колонок нет значения по умолчанию: строка, записанная
до обновления или версией 0.13, хранит в них NULL, и `get_cached_counts` отдаёт
для неё «нет кэша» — карточка показывает «Loading tasks», а не «No tasks» с
нулями. Миграции теперь выполняются в транзакции вместе с записью номера
версии: миграция 4 — это четыре команды, и сбой посередине иначе оставил бы
базу, которую следующий запуск не смог бы довести до конца.

**Что проверить, если сломается.** Карточка пишет «The server sent no task
counts» — `/api/beads` ответил без `counts`: либо это частичное чтение (главная
его не делает), либо ответ пришёл от старого сервера. Числа на главной не
сходятся с доской — сравнить `counts` в ответе `/api/beads` с `/api/statuses`
этого проекта: группу статуса решает именно этот список. В журнале сервера
строка `read project statuses` при загрузке главной означает, что в проекте
есть свой статус и список читался (раз в 3 минуты на проект).

**Что оставлено как есть.** Главная по-прежнему загружает весь список задач
проекта, хотя ей нужны только числа, — отдельной лёгкой точки для счётчиков
нет. Строки кэша от 0.13 без групп заполнятся при первой загрузке главной.
Цвета тем не менялись: «заморожено» берёт существующую `--text-muted`.
