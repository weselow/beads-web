# 2026-09-29 — комментарий со страницы в проектах dolt:// (beads-web-3zm)

Комментарий со страницы раньше шёл через `/api/bd/command`, которому нужна
папка проекта, поэтому в проектах `dolt://` (без папки) он не добавлялся. Теперь
есть `POST /api/beads/comment {path, id, text}` (`server/src/routes/comment.rs`),
устроенный как `/api/beads/close`: для `dolt://` — `DoltManager::add_comment`
в `server/src/dolt.rs` (проверка, что задача есть, иначе 404; вставка строки в
`comments` с автором `web-ui`; `DOLT_COMMIT` с сообщением
`web-ui: comment <id>`), для папки — `bd comment -- <id> <text>`. Пустой id или
текст из одних пробелов — 400. На странице `addComment` в `src/lib/cli.ts`
вызывает `api.beads.comment`; `comment-list.tsx` не менялся. Почему так:
в bd 1.3.0 `comments.id` — CHAR(36) без значения по умолчанию (миграция 0051,
bd сам придумывает id), поэтому сервер посылает свой UUID; у старых баз, где
id — BIGINT с автоувеличением, id не посылается — тип столбца читается из
`information_schema` перед вставкой. `--` в аргументах bd обязателен: без него
bd 1.3.0 принимает текст, начинающийся с `-`, за флаг и падает с
`unknown shorthand flag`. Заодно чтение комментариев через SQL упорядочено по
`created_at, id`, а не по одному `id`: id — случайные UUID, и новый комментарий
иначе попадал в случайное место списка. Если сломается — сначала смотреть
журнал сервера (`comment added` / `adding a comment failed`) и тип столбца
`comments.id` в базе проекта. Сознательно не сделано: журнал событий bd
(`bd_events_journal`) при записи через SQL не пополняется — как и у закрытия и
правок через SQL; два комментария в одну секунду могут показаться в любом
порядке (bd в этом случае сдвигает время на секунду, мы — нет).
