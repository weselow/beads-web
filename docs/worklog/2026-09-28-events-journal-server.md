# 2026-09-28 — сервер: копия задач в памяти и журнал bd events (beads-web-7ux.4.1)

Для файловых проектов во встроенном режиме Dolt `/api/beads` на каждый запрос
запускал полный `bd export` (в `bd sql` встроенный режим не умеет). Если в
проекте включён журнал (`events-journal: true` в `.beads/config.yaml` или
переменная `BD_EVENTS_JOURNAL`), сервер теперь один раз читает всё, держит
копию в памяти и дальше спрашивает только `bd events tail --since N`. Код —
`server/src/routes/journal.rs`, подключение — ступень 2 в `read_beads`
(`server/src/routes/beads.rs`). Ответ: `source: "cli-journal"`, `complete: true`.
На пробном проекте (1002 задачи, 10 тыс. записей журнала, отладочная сборка)
запрос стал занимать ~1–1,4 с вместо 6,4–8 с; первое полное чтение — 6–10 с.

**Почему так.** В записи журнала нет комментариев и связей, поэтому они
берутся из копии, а связи и родитель правятся записями `dep_add`/`dep_remove`.
Последний номер журнала дёшево не узнать, поэтому при полном перечитывании он
ищется чтением журнала потоком (без хранения в памяти); если прошлый номер
известен — только хвост после него. Каждое дочитывание начинается с записи,
виденной в прошлый раз (`--since N-1`): если её нет — журнал подменили, и всё
перечитывается заново. Раз в 10 минут и по `full=1` — полное перечитывание,
потому что `bd dolt pull` в журнал не попадает. Журнал выключили — копия
выбрасывается, чтобы после повторного включения не продолжить со старой.

**Что проверить, если сломается.** В журнале сервера строки
`journal baseline started/finished` (с `duration_ms`), `journal catch-up
applied`, `events journal read failed, falling back to bd CLI`. При любой
ошибке сервер уходит на прежний путь (`source: "cli"`), так что симптом
поломки — снова медленные ответы, а не пустая доска. Ошибка «обрезанного
журнала» (`events_journal_truncated`) приходит в stdout с кодом выхода 1 — если
bd изменит это, чтение будет падать на прежний путь. Проверка на свежем
проекте: `git init` + `bd init --prefix t -q` + `bd config set events-journal true`
во временной папке, затем сравнить обычный ответ с ответом `full=1`.

**Что намеренно не трогали.** `bd serve`, `watch.rs` и поток уведомлений,
ступень 0 и пути `dolt://`, страницу (отдельная задача beads-web-7ux.4.2) и
переключатель журнала в настройках.
