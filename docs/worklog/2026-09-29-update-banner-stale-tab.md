# 2026-09-29 — плашка обновления не врёт во вкладках, открытых до обновления (beads-web-ud3)

После обновления 0.12.4 → 0.13.0 вкладка, открытая до него, продолжала писать
«You're running v0.12.4» и предлагать обновиться: `src/components/update-banner.tsx`
спрашивал версию только при открытии и раз в час. Теперь он спрашивает ещё и
когда вкладка снова становится видимой (`visibilitychange`), но не чаще раза в
30 с. После нажатия «Update & Restart» страница больше не перезагружается на
первый ответ `/api/health` (его мог дать ещё старый сервер): она опрашивает
`/api/version/check` раз в секунду, пока `current` не станет той версией, которую
ставили, и только тогда перезагружается; через 20 попыток — всё равно
перезагружается. На сервере `perform_update` в `server/src/routes/version.rs`
решает через `plan_update`, сравнивая последнюю версию с работающей тем же
`is_newer`, что и `version_check`: равная или неизвестная версия — ответ
`{"status":"up_to_date","message":"Already up to date (vX)"}` без скачивания и
перезапуска. Страница на такой ответ перепроверяет версию и прячет плашку.

**Почему так.** В ответе «уже обновлено» нарочно нет поля `error`: страница из
старого выпуска считает любой ответ без ошибки началом перезапуска и
перезагружается — для устаревшей вкладки это и есть лучший исход. С полем
`error` она бы показала красную надпись и осталась со старой плашкой.

**Что проверить, если сломается.** Плашка снова врёт после обновления — в
журнале сервера при повторном нажатии должно быть `Update requested, but vX is
already the latest`. Страница после обновления висит ~25 с на «Restarting
server...» и в консоли `Update: server did not report vX after 20 attempts` —
новый сервер не поднялся (сработал откат в скрипте обновления) или отдаёт
другую версию, чем обещал GitHub.

**Что оставлено как есть.** Скрипты обновления, проверка `/api/health` внутри
них и часовой кэш ответа GitHub не менялись.
