# 2026-09-28 — обновление bd 1.1.0 → 1.3.0 и проверка beads-web (beads-web-7ux)

bd 1.3.0 при первом запуске переделывает схему базы (v53 → v66, около 28
шагов), и отменить это можно только откатом схемы. Поэтому обновление шло по
порядку: проба на копиях → три полных репетиции на изолированных копиях всех
проектов машины → окно работ с остановленными агентами: нетронутые копии всех
`.beads`, выгрузка каждого проекта старой версией, замена bd, открытие каждого
проекта новой версией и сверка выгрузок. Сверка — по каждой записи, после
нормализации: в 1.3.0 у комментариев новые внутренние id, а порядок
зависимостей в выгрузке другой.

beads-web 0.12.4 с bd 1.3.0 работает без правок кода: прямое чтение из базы
(ступень 0), чтение через bd, частичное чтение (`--updated-after`), все
команды записи, которые вызывает сервер (`create` с описанием и без,
`--parent`, `update` всех полей, `close`, `comment`, `show`, `list`,
`memories`/`remember`/`forget`). `bd sql` во встроенном режиме как не
поддерживался, так и не поддерживается — комментарии там читаются запасным
путём через `bd export`.

**Что проверить первым, если сломается.**

- Доска вдруг показывает старые задачи и меньше, чем должно быть: скорее всего
  где-то остался bd 1.1.0 (первым в PATH, в WSL, рядом с beads-web). Он
  отказывается открывать базу v66, и beads-web молча уходит на старый
  `issues.jsonl`. Смотреть поле `source` в ответе `/api/beads` и журнал
  сервера. Само молчание — ошибка, заведена как beads-web-cgl.
- `bd count` работает, а `bd list` падает «table not found: leases»: переделка
  схемы не прошла. Причины, найденные при обновлении: незафиксированные
  изменения в рабочем наборе Dolt (bd 1.3.0 тогда молча пропускает переделку,
  видно только с `BD_DEBUG=1`; лечится `bd dolt commit` старой версией до
  обновления); запрет на переделку базы с удалённым хранилищем Dolt (нужно
  `BD_ALLOW_REMOTE_MIGRATE=1` на единственной машине); отметка
  `.beads/.local_version` уже равна 1.3.0 после неудачной первой попытки —
  вернуть в неё `1.1.0` и повторить.
- Проект подключился к серверу другого проекта («database … not found on Dolt
  server at 127.0.0.1:3307»): bd 1.3.0 берёт порт из `.beads/dolt-server.port`,
  а если тот мёртв — из `listener.port` в `.beads/dolt/config.yaml`, и молча
  подключается к любому серверу на этом порту. Порты в `dolt/config.yaml`
  разных проектов не должны совпадать. Та же причина увела одну пробную
  копию `.beads` в настоящую базу — копиям перед запуском bd надо прописывать
  свой свободный `listener.port`.

**Что намеренно не трогали.** `bd serve` — в 1.3.0 он не работает со
встроенным режимом, ждём поддержки. Журнал изменений `bd events` вместо
перечитывания раз в 15 секунд — отдельная задача beads-web-7ux.4. Перевод
проектов из встроенного режима в серверный — не нужен ни для обновления, ни
для `bd events`.
