# 2026-09-29 — закрытие задачи и эпика в проектах dolt:// (beads-web-c0d)

Раньше `closeBead` (`src/lib/cli.ts`) шла через `/api/bd/command`, которому
нужна папка проекта, поэтому в проектах `dolt://` не работали кнопка
Dismiss в панели Ideas и закрытие эпика. Теперь есть отдельный запрос
`POST /api/beads/close {path, id, reason?}` (`server/src/routes/close.rs`):
для `dolt://` задача закрывается по SQL (`DoltManager::close_bead` в
`server/src/dolt.rs` — одна команда UPDATE со статусом, `closed_at`,
`close_reason`, `updated_at`, затем `DOLT_COMMIT`), для папки — через
`bd close` с причиной одним аргументом `--reason=…`. `closeBead` на странице
теперь зовёт `api.beads.close`, порядок аргументов прежний, так что
`epic-card.tsx` не менялся; у панели Ideas ушли свойства `fsPath`,
`isDoltOnly` и `canDismiss`. Поведение повторяет bd 1.3.0, проверенное на
пробном проекте: без причины bd пишет `close_reason = "Closed"`, и SQL-путь
пишет то же; `bd update --status closed` ставит `closed_at`, а переход в
любой другой статус снимает и `closed_at`, и причину — так же теперь делает
`PATCH /api/beads/update` для `dolt://` (`push_closed_sets` в `dolt.rs`).
Идентификатор задачи в тексте сообщения `DOLT_COMMIT` экранируется
(`commit_statement`, теперь и при создании, и при изменении задачи), всё
остальное — только параметры запроса.
**Если сломается:** сначала журнал сервера — строки `bead closed` и
`closing a bead failed` с полями `via` (`dolt` или `bd`) и `status`; 404
значит, что строки с таким id в базе нет. SQL-путь вживую на настоящем
`dolt://`-проекте не проверялся (нельзя писать в чужие базы), только
тестами сборки запроса; путь через `bd close` проверен на пробном проекте.
**Оставлено как есть:** остальные команды в `cli.ts` (комментарий, смена
статуса, заголовка, описания, создание) по-прежнему идут через
`/api/bd/command` и в проектах `dolt://` не работают. Повторное закрытие
уже закрытой задачи по SQL перезаписывает `closed_at` и причину, тогда как
`bd close` их не трогает; страница такое закрытие не предлагает.
